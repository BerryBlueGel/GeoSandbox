# 存储管理与恢复区清理

更新：2026-11-18。入口为“空间装配 → 交付 → 存储与清理”。复用既有恢复点清单、资源哈希、原子写入与文件任务入口。

## 本批范围

容量面板分类显示恢复区、原始导入与预览、导出成果、原生 GIS 任务和日志的逻辑字节数、文件数，以及所在磁盘可用空间。恢复配额仍为 2 GiB，统计范围是恢复区的 `assets/documents/records`；回执、临时文件另计在目录占用中。统计是扫描时刻的结果，磁盘可用空间也受其他程序影响。

清理只操作 `.geosandbox/checkpoints` 中严格匹配标识的普通文件。原始导入目录、导出目录、运行任务、日志、用户外部文件及源码不在删除范围内；不执行递归删除。

## 使用步骤

1. 刷新容量，展开“选择旧恢复点”。管理列表显示最早 200 条；既有恢复入口仍显示最近 20 条。
2. 选择不再需要的旧恢复点。每个项目按项目 ID 保留最新一条，同名项目可通过短 ID 区分。改名和重开已保存的项目包沿用原 ID。缺少项目 ID 的旧版恢复点逐条保护，打开旧项目包后保存即可把生成的 ID 写入新包。
3. 可勾选同时清理未引用旧文档和资源，点击“预览清理清单”。清单显示具体文件、原因、预计释放字节和保留数量，每批最多 500 个文件。
4. 核对清单后勾选永久删除确认，再点击执行。文件删除不可撤销，不加入项目撤销栈；重要版本应先另存便携项目包。
5. 执行后核对回执，恢复点列表和容量刷新。剩余候选可再次预览；未选恢复点不会因为超过显示数量而自动删除。

页面本身不会自动清理数据。预览或更改选择不会修改当前项目，不增加项目处理历史，不使项目变成未保存。

## 引用、保存并发与失败保护

- 服务读取全部恢复点记录、文档哈希与清单，重新计算保留恢复点的资源引用；共享资源不重复计入可清理空间。
- 文档和资源只有在未被保留恢复点引用、文件最后使用时间超过 24 小时时才进入清单。近期及未完成写入的文件保留。
- 保存流程检查或复用已有资源时更新使用时间。在资源检查与项目文档提交之间，该资源受到 24 小时保护；执行与保存提交使用同一个恢复区锁。
- 清单带版本指纹。新增恢复点、上传资源、使用时间变化或文件变化，会使执行请求失败，要求重新预览，不能静默扩大删除范围。
- 恢复记录、文档或资源存在/长度检查发现异常时锁定清理。预览校验文档哈希和清单结构，不为容量扫描重新读取并哈希全部资产；恢复项目时仍执行完整资源哈希校验。
- 链接、Windows 联接目录和异常路径不会被跟随删除。待写入文件、恢复下载临时包和未知文件不作为普通垃圾清理。
- 删除顺序为选定记录、无引用内容。发生文件锁定或写入错误即停止；保留恢复点依赖的文件不进入删除清单。

## 持久回执

执行前先原子写入 `.geosandbox/checkpoints/cleanup-receipts/<编号>.json`，不能写回执就不开始删除。执行开始后关闭取消，避免声称已经删除的数据能被取消回来。

回复丢失时按同一编号查询回执，不重复 POST。完成状态记录实际文件数和逻辑字节；部分失败保留实际已清理数量。服务中断或最终回执无法提交时显示未确认，重启后旧运行回执标为中断，数量为未知，要求重新扫描，不自动重跑旧清单。

| 后端接口 | 用途 |
| --- | --- |
| GET `/sandbox/storage` | 分类容量、可管理旧恢复点、保护及异常状态 |
| POST `/sandbox/storage/preview` | `checkpointIds`、`orphanedFiles`，生成清单和指纹 |
| POST `/sandbox/storage/cleanup/{编号}` | 同一选择和 `fingerprint`，执行已核对清单 |
| GET `/sandbox/storage/receipts/{编号}` | 查询持久回执，包括重启后的中断状态 |

前端沿用 `/sandbox-api` 代理，接口沿用本地来源检查。清理不是操作系统级的访问隔离，也不代替公网部署所需的用户权限。

## 验收与剩余工作

验收入口为 `scripts/geosandbox-accept.ps1 -Build`。存储模块测试覆盖共享资源、同名项目分别保留最新恢复点、改名后沿用 ID、旧版恢复点保护、容量释放、保存间隙资源保护、旧清单拒绝、损坏图锁定、Windows 联接目录、部分失败、丢回复、回执重读和最终回执写入失败。

删除用例只在该目录内新建的隔离数据区运行，日常数据区只读扫描与预览，独立比较其文件哈希。页面验收同时校验清理后保留项目仍能恢复。

本轮还修正了恢复项目后的状态时序：最终提交已完成时，随后发生的渲染器或界面恢复通知不能再将该任务误报为取消；提交之前的新编辑和项目切换仍会阻止旧结果应用。

后续工作包括总容量策略、自动保留规则、操作系统内存限制和真实业务规模基准。

## 任务与成果归档

在“交付 → 任务与成果归档”选择“导出成果”或“原生 GIS 任务”，再切换“未归档”和“已归档”。成果列表按文件分页，保留项目包各版本及 GLB、JSON 等文件。项目包可从列表校验并打开，其他成果可下载。

归档后条目从常用列表收起。“取消归档”可将其放回。等待、运行和正在停止的任务需要先完成或停止。归档标记保存在 D 盘，刷新或重启后仍有效。成果继续使用原有下载地址和保存回执，后台任务继续使用原有任务编号和结果地址。文件留在原位置，归档不会释放磁盘空间。释放空间的恢复区清理规则见上文。

最终检查：92 项前端、156 项后端、固定成果校验、TypeScript/生产构建与相关 ESLint 通过。页面使用项目 Playwright 与本机 Edge（当前未提供 Browser 插件），检查 1280×720 和 390×844；无未捕获页面异常，受控 409/丢回复网络错误及底图样式的空值过滤警告单独记录。隔离区清理 3 个文件约 2.10 MiB，保留的 2 个恢复包完整校验并通过界面恢复；日常数据区 130 个文件哈希不变。该结果是构造场景功能验收，不是全站容量、磁盘吞吐或真实数据压力基准。
