# GeoSandbox 单用户服务器部署

一个实例对应一个操作者及其数据卷。容器端口只绑定宿主机回环地址，用户通过宿主机的 HTTPS 反向代理访问。服务复用 GeoLibre 的 Nginx Basic Auth 和 FastAPI 回环令牌。 [Docker 端口绑定](https://docs.docker.com/engine/network/port-publishing/) · [Nginx 身份认证](https://nginx.org/en/docs/http/ngx_http_auth_basic_module.html)

## 启动

在服务器安装 Docker Engine 和 Compose，取得同一 Git 提交的源码。将以下配置保存在仓库外的专用环境文件中，并限制其读权限。`GEOSANDBOX_PUBLIC_ORIGIN` 填浏览器使用的准确来源，包含协议和必要端口，省略默认端口和末尾斜杠。`GEOSANDBOX_VOLUME` 指向预先建立的数据目录，Windows 冒烟时可用 D 盘路径。线上地址用 HTTPS。仅在回环冒烟时可将来源设为 `http://127.0.0.1:8080`。

```dotenv
GEOSANDBOX_PUBLIC_ORIGIN=https://sandbox.example.net
GEOSANDBOX_VOLUME=/srv/geosandbox/data
GEOSANDBOX_PORT=8080
GEOLIBRE_AUTH_USER=owner
GEOLIBRE_AUTH_PASSWORD=替换为自己的强密码
# Optional, injected server-side by the operator
# DEEPSEEK_API_KEY=
# DEEPSEEK_MODEL=deepseek-flash
```

```sh
docker compose --env-file /path/to/geosandbox.env -f compose.geosandbox.yml config --quiet
docker compose --env-file /path/to/geosandbox.env -f compose.geosandbox.yml up -d --build --wait
```

如已取得 Linux amd64 的 `GeoSandbox-0.1.0-linux-amd64.tar.gz`，将镜像、SHA-256 文件和 `compose.geosandbox.yml` 放在同一个部署目录。校验后导入镜像，即可从该目录启动服务。

```sh
sha256sum -c GeoSandbox-0.1.0-linux-amd64.sha256
docker load -i GeoSandbox-0.1.0-linux-amd64.tar.gz
docker tag geosandbox:0.1.0 geosandbox:local
docker compose --env-file /path/to/geosandbox.env -f compose.geosandbox.yml up -d --no-build --wait
```

反向代理将站点转发到 `http://127.0.0.1:8080`，传递 `Authorization` 和 `Origin`，允许 300 MiB 请求体，读取超时至少 180 秒。发布端确认 TLS 证书正常。DeepSeek 由部署人员通过环境配置。未提供 Key 时，应用仍可编辑和导出。

## 发布检查

1. 未带账号访问页面和 `/sandbox-api/status` 得到 401。使用有效账号后页面和状态接口返回 200。`/healthz` 用于宿主机健康检查。
2. 同站点导入公开样本，生成项目包，重启容器后从项目列表重新打开。核对文件散列、模型锚点和报告。使用不同来源提交写操作应返回 403。普通 `/sidecar/` 中的沙盒和 AI 前缀受到单独限制。
3. AI 启用时，由部署人员使用固定短提示验证连接。公开配置和接口响应只显示模型名及配置状态。
4. 保留一份数据目录的备份和原镜像标签，再升级。升级前停止写入并做快照。回滚时用原镜像和该版本备份的数据目录启动，以免旧程序覆盖升级后的数据。

数据存放于挂载目录下的 `geosandbox` 子目录。项目包、恢复点、原件、后台任务及归档均应一起备份。Compose 限制容器内存、进程数和日志占用，主机仍需为 GIS 结果及项目包预留存储。此部署配置面向空间装配和 GIS 交付，镜像省略上游可选的 JupyterLite 笔记本及其入口。
