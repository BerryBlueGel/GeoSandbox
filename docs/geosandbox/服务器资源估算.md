# 服务器资源估算

2026-11-16，基于当前本地版本。以下为工程估算，不是已完成的 Linux 服务器压力测试或并发人数承诺。

| 场景                            | CPU    | 内存        | SSD                   |
| ------------------------------- | ------ | ----------- | --------------------- |
| 单人、小型演示、少量处理        | 2 核   | 2 ～ 4 GB   | 20 GB 起              |
| 个人日常混合数据处理            | 4 核   | 8 GB        | 40 ～ 60 GB           |
| 多任务或较重 GIS 处理的后续部署 | 8 核起 | 16 ～ 32 GB | 100 GB 起，按数据增加 |

目前可按 4 核、8 GB、约 50 GB SSD 规划个人试运行。大量模型、影像、复杂几何与同时处理的任务会改变峰值；先测单任务，再决定并发，不能把保护上限当作流畅容量。

本机实测逻辑文件大小：前端 `dist` 约 198.5 MiB，当前 Windows Python 虚拟环境约 413.8 MiB，不含开发依赖、操作系统、业务数据和按需下载的额外处理运行环境。Linux wheel、系统 GDAL/PROJ、容器与日志的大小会不同。后端空闲工作集很小不能代表 GIS 处理时的峰值，因此不以空闲内存决定配置。

三维显示主要由用户浏览器承担；服务器负责本地数据/恢复点、GIS 原生处理和 DeepSeek 转发。这版使用云端 DeepSeek API，服务器不需要为大模型配显卡；用户电脑的内存、显卡和浏览器仍影响三维体验。

若服务器上执行前端安装和构建，建议至少 8 GB 内存，开发依赖/缓存另留空间；本地构建后上传静态产物能减少服务器占用。生产运行不需要把整个开发目录、node_modules 和本地缓存一起上传。

磁盘按“系统与软件 + 原始数据 + 派生与导出 + 恢复资源 + 临时文件 + 20%～ 30% 余量”规划。当前恢复区累计上限 2 GiB，达到后暂停新增；手动导出和业务数据是另外的占用。大数据版还需要容量管理和安全清理。

当前启动器只监听本机，面向个人本地使用。公网部署前还需身份验证、项目隔离、允许来源配置、并发/配额限制、HTTPS 反向代理及 Linux 凭据配置；不能只扩大监听地址便宣称已完成生产部署。本次没有修改监听范围或发布到公网。
